# 值班台 · 三副本单对象存储

单对象网页存储的值班工具：一个对象固定三个副本，分别落在 `replica-1/`、
`replica-2/`、`replica-3/` 三个独立本地目录；元数据（版本摘要、副本状态、巡检记录、
操作日志）存于 SQLite。上传/替换 ≤ 1 MiB 文件、下载、模拟损坏副本、发起巡检修复，
全部可在网页完成。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。

数据保存在名为 `object-data` 的 Docker 卷中，容器重建/重启不会丢失。停止：

```bash
docker compose down
```

（若连数据卷一起删除：`docker compose down -v`，对象与巡检历史会一并清空。）

### 不使用 Docker 时

```bash
python3 -m pip install -r requirements.txt
DATA_DIR=./data uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`DATA_DIR` 下会生成 `app.db`、`replica-1/`、`replica-2/`、`replica-3/`。

## 行为约定

> 部署假设：单容器、单进程（Compose 里只有一个 uvicorn worker）。三副本目录和 SQLite
> 都在本机 `DATA_DIR`，不支持多进程/多实例同时写同一目录。

- **版本登记**：每次上传生成一个新版本，记录 SHA-256、长度、文件名和序号，三个副本
  原子写入并各自校验后才切换当前版本指针。文件名只取 basename，不参与路径拼接。
- **下载**：按页面所报的 `version_id` 读取该登记版本的副本字节（不带参数时取当前
  版本），读到的完整字节重新计算 SHA-256，必须与登记的摘要和长度都相符才发送；否则
  返回 409 并说明原因，绝不发送不完整或错误字节。未知版本返回 404。
- **模拟损坏**：把指定副本原地改写为不同字节（内容翻转），不触碰其它副本；操作记入
  日志。三份可以逐一破坏。
- **巡检修复**：逐个读取三个副本并核对大小与摘要。只要有一份通过验真，其余副本仅从
  已验真副本复制：先写入同目录临时文件并校验，锁内确认当前版本未变化后 `os.replace`
  原子覆盖，再复核摘要。三份都未通过验真时结论为「不可恢复」，不写任何副本。
- **替换交错**：巡检任务固定在其开始时的 `version_id` 上。提交结果前在写锁内检查当前
  版本指针；若已被替换，本次巡检只记为 `superseded`，不更新新版本的副本状态、不修改
  新版本文件，也不会把新版本误报为已修复。
- **中断与重启**：`running` 状态的巡检在下次启动时标记为 `interrupted`；清理临时文件
  和未登记残留文件；随后重新读取磁盘上的三个副本，页面显示的「可读副本 N/3」始终是
  实际计算结果，不信任数据库缓存。再次巡检会对仍未通过的副本继续修复。
- **页面状态**：每次渲染都重新校验当前版本的三个副本，不直接采用上次巡检的缓存。
- **副本目录容量上限**：三个副本目录各自独立设上限（默认 32 MiB），可在网页
  「副本目录容量」卡片随时调整，设置存入 SQLite，重启后保留；也可用环境变量
  `REPLICA_QUOTA_BYTES`（统一默认值）和 `REPLICA_<槽位>_QUOTA_BYTES`（单目录覆盖，
  槽位 1/2/3）指定首次启动的默认值。网页与 `/api/status` 实时显示每个目录的实际占用、
  在途预留、可用空间与上限，空间不足时明确指出被阻塞的目录。
- **占用口径**：目录内所有普通文件都计入实际占用——正式副本、新版本写入暂存
  （`.tmp-*`）、巡检修复暂存（`.tmp-repair-*`）以及未清理的残留文件。写入前先在
  进程内「在途预留账本」登记本次字节数，写完或失败立即归还；上传与巡检修复交错时
  共用同一本账，同一块空闲空间不会被两个操作重复使用。
- **超限/写盘失败语义**：任一副本目录放不下本次写入时，在写盘前整体拒绝并指明阻塞
  目录；不会删除仍应保留的旧版本，原先可下载的版本保持可读。写盘失败（OSError）同样
  清理本次临时文件并放弃替换。巡检修复遇到容量不足或写盘失败时结论为 `failed`，绝不
  报修复成功，已通过验真的副本不受影响；释放空间（清理残留或调高上限）后可直接重试。
- **重启核算**：启动时先清理暂存文件与未登记残留，再按磁盘上的实际文件重新扫描各目录
  占用；配额以数据库里的值班设置为准。空间释放后无需迁移数据即可重试。
- **历史版本**：版本登记与巡检历史长期保留；副本文件只保留最近 10 个版本，超出部分
  的副本会清理，旧版本下载随之返回 409，绝不把它当作当前版本交付。

## 目录

```
app/
  main.py          FastAPI 路由、请求体 1 MiB 上限、下载交付校验、配额设置/残留清理
  storage.py       版本/副本/SQLite、原子写、容量上限与在途预留账本、巡检记录、修复提交
  maintenance.py   巡检修复流程（钉住版本、只复制已验真副本、容量/写盘失败即 failed）
  templates/       操作网页
  static/          样式
tests/test_app.py   上传/下载/损坏/修复/交错/重启恢复测试
tests/test_quota.py 容量上限/空间不足/交错预留/重启核算/写盘失败测试
Dockerfile, docker-compose.yml
```

## 自测

```bash
python3 -m pip install -r requirements.txt httpx pytest
python3 -m pytest -q
```

覆盖场景包括：1 MiB 边界与超限拒绝、下载摘要校验与全坏拒绝、仅从已验真副本修复、
三份全坏判定不可恢复、修复中断后重启恢复并继续巡检、巡检修复中途替换对象（旧巡检
不得覆盖新版本/误报新版本）、过期版本操作被拒绝、路径穿越文件名净化，以及容量专项：
配额不足时上传被整体拒绝且旧版本保持可读、阻塞目录与占用明细上页面、暂存与残留计入
占用、上传与巡检修复交错时同一块空闲空间不被重复预留、巡检遇容量不足记 `failed`
而非成功、空间释放后重试成功、重启后按实际文件重算占用且配额持久化、模拟写盘失败时
旧版本与临时文件的处置。
